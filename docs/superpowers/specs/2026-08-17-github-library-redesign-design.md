# GitHub 收录库重构设计

日期：2026-08-17
范围：Pulse Electron renderer 的 GitHub 收录页面
视觉方向：策展阅读库

## 1. 目标

将 GitHub 收录页从“添加表单 + 管理列表 + 详情抽屉”重构为一个更适合长期使用的个人开源项目库：

- 更快找到已收录项目。
- 更快理解项目价值和使用方式。
- 更明确地发现新版本、Release 和失败检查。
- 保留现有收录、批量添加、置顶、README、AI 解析、更新检查、备份导入导出能力。

成功标准：用户进入页面后，能够在两次操作内找到目标项目，并在项目卡片或详情面板中直接判断“项目是什么、是否值得看、是否有更新”。

## 2. 非目标

- 不改 GitHub API、主进程 IPC channel 或 Token 处理边界。
- 不引入服务端账户、云端同步或新的远程数据源。
- 不新增必须迁移的 localStorage 数据结构。
- 不在本次工作中重构 Pulse 其它模块的导航或全局设计系统。

## 3. 当前约束与已有能力

当前 GitHub 模块由以下能力组成：

- `GithubPage`：页面编排、详情抽屉和更新检查结果提示。
- `GithubAddForm`：单条/批量收录入口。
- `GithubProjectList`：搜索、排序、语言/标签筛选、列表/卡片视图、分页和项目操作。
- `GithubProjectDrawer`：README、AI 解析、Release 更新三个 tab。
- `github-projects-store.ts`：本地项目状态、持久化和现有服务 façade。
- `github-project-repository.ts`、`github-readme-service.ts`、`github-release-checker.ts`、`github-backup-service.ts`：已拆分的业务服务。

本次重构应在这些边界上继续深化，而不是把 API、持久化和 UI 逻辑重新耦合。

## 4. 信息架构

页面改为“策展侧栏 + 项目浏览区 + 项目阅读面板”的结构。

### 4.1 页面头部

页面标题改为“我的开源库”，副标题显示已收录数量和待处理更新数量。

主操作：`添加项目`。
次操作：`检查更新`。
低频操作：备份导入导出、密度和设置入口放入更多菜单或设置区域。

添加入口默认打开轻量弹层，支持单条和批量两种模式，避免输入区域长期占据页面首屏高度。

### 4.2 策展侧栏

侧栏只提供现有数据可以可靠支持的筛选，不引入新的分类持久化模型：

- 全部项目。
- 最近查看。
- 待处理更新。
- 从项目 `language` 派生的语言分组。
- 从 GitHub `topics` 和 `aiParse.tags` 合并派生的标签分组。

侧栏当前筛选条件应与主区域搜索条件组合生效，并在主区域以可移除的筛选 chip 回显。

### 4.3 项目浏览区

默认采用卡片网格，卡片包含：

- 仓库名和 GitHub 链接。
- 一句话简介。
- 语言、Star、许可证、主页等关键元数据。
- topics / AI tags。
- AI 摘要（已解析时显示）。
- Release 状态：新版本、已最新、未检查或检查失败。
- 置顶和更多操作。

卡片不再同时铺开所有操作按钮；主要动作是打开项目和进入阅读面板，低频操作收进卡片菜单。

搜索、排序和筛选保留现有语义。分页继续保留，以避免一次渲染大量 README 摘要造成界面拥挤。

### 4.4 项目阅读面板

点击卡片后打开右侧阅读面板，保留现有抽屉的低风险实现路径，但重新组织头部和内容：

- 顶部固定项目名、语言、Star、主页和“在 GitHub 打开”。
- 主要内容切换为“概览 / README / AI 解析 / 更新”。
- 概览展示项目简介、关键标签、最新版本和 AI 一句话定位。
- README、AI 解析、Release 内容沿用现有服务和加载态。
- 有更新时在面板头部与“更新”页签同时提供明确状态和“标记已读”。

## 5. 视觉与交互规则

- 延续 Pulse 现有浅色/深色主题、系统字体、轻边框和低阴影风格。
- GitHub 使用紫色品牌强调色；AI 摘要使用柔和紫色；更新使用蓝色/绿色；错误使用红色。
- 页面基础表面优先使用间距、对齐和分组建立层级，避免卡片套卡片。
- 卡片状态必须可区分：默认、置顶、有更新、待解析、README 缺失、API 失败。
- 所有按钮保留可见 focus ring、明确 aria-label 和 disabled 状态。
- 窄窗口下侧栏可折叠为筛选按钮，项目网格降为单列，卡片操作进入更多菜单。
- `Cmd/Ctrl+F` 继续聚焦页面搜索框，现有快捷键行为不改变。

## 6. 组件与代码边界

建议新增或重命名以下 renderer 组件：

- `GithubLibraryHeader`：统计、添加项目、检查更新。
- `GithubLibrarySidebar`：分类、状态、语言和标签筛选。
- `GithubProjectGrid`：项目网格和空/无匹配状态。
- `GithubProjectCard`：单项目展示、状态和低频操作菜单。
- `GithubProjectPanel`：项目概览、README、AI 解析、更新内容。
- `GithubAddDialog`：单条/批量添加弹层。

`GithubPage` 只负责编排这些组件、持有当前项目和当前面板 tab；不继续承载排序、筛选、批量操作和 Toast 细节。

从 `github-projects-store.ts` 抽出纯派生逻辑，例如筛选、排序、标签集合、统计和卡片状态，形成可独立测试的 selector 文件。现有 repository、release checker、README service 和 backup service 保持独立。

## 7. 数据流与状态

1. `GithubLayout` 继续负责加载项目和设置，以及后台检查调度器。
2. `GithubPage` 读取项目 signal，并把操作回调传给页面子组件。
3. 派生 selector 根据搜索词、侧栏筛选和排序返回稳定的可渲染项目集合。
4. 卡片操作调用现有 store façade，不直接绕过 repository 或 service。
5. 详情面板只通过现有 `refreshGithubReadme`、`parseGithubProjectAi`、`fetchGithubRelease` 等入口更新项目。
6. localStorage 持久化格式不变；导入数据继续走现有合并逻辑。

## 8. 加载、错误和空状态

- 首次加载：页面显示结构化骨架，不闪现“还没有项目”。
- 空库：引导用户添加第一批项目，并提供单条/批量添加入口。
- 无匹配：显示当前搜索和筛选条件，并提供清除筛选动作。
- API 限流：在相关项目或检查摘要处显示剩余次数/重置提示，保留重试入口。
- 单项目失败：错误只绑定到该项目，不阻塞其它卡片浏览。
- README 缺失：显示明确空态，保留刷新和打开 GitHub 原文动作。
- AI 解析失败：显示失败原因和重试，不覆盖原有 README。
- 检查更新部分失败：保留成功结果，同时提供“重试失败项”。

## 9. 验证计划

### 单元与组件

- selector：搜索、排序、语言/标签组合筛选、置顶排序和更新统计。
- card：版本状态、AI 摘要、置顶和更多操作。
- add dialog：单条提交、批量提交、重复项目和失败明细。
- panel：概览、README、AI、更新 tab 的加载、空态、错误和重试。

### 静态与构建

- TypeScript 类型检查。
- GitHub renderer 相关 Vitest。
- 全量 Vitest。
- `git diff --check`、lint 和 renderer/main 构建。

### 实际界面

- Electron 中打开 GitHub 收录页面。
- 验证空库、已收录项目、搜索/筛选、卡片打开阅读面板。
- 验证更新状态、AI 解析入口、Release 时间线和错误重试。
- 验证窄窗口下的侧栏折叠、单列卡片和操作菜单。

## 10. 分阶段交付

1. 先抽出 selectors 和页面骨架，保持现有 store/API 行为。
2. 重构头部、添加弹层、侧栏和卡片网格。
3. 重构项目阅读面板与四个内容视图的入口。
4. 补齐空态、错误态、响应式和可访问性。
5. 完成组件测试、构建和 Electron 实际界面验证。

## 11. 验收标准

- 现有项目记录无需迁移即可显示。
- 单条和批量收录、搜索、排序、筛选、置顶、删除、备份和更新检查均可用。
- 用户无需先打开详情面板即可看见项目简介、核心标签和版本状态。
- 详情面板可以连续完成概览、README、AI 解析和更新查看。
- 失败和空状态不会清空已有项目或覆盖成功数据。
- 浅色、深色和窄窗口布局均通过静态与实际界面验证。
